### 4.1 윤리적이고 공정한 AI 시스템 개발

#### 4.1.1 책임감 있는 AI의 핵심 차원

| 차원 | 정의 |
|---|---|
| 공정성 | 연령·거주지·성별·민족 등에 관계없이 편견 없이 공평하게 대우 |
| 설명 가능성 | 특정 결정을 내린 이유를 인간 관점에서 설명 가능(예: 대출 거부 사유) |
| 견고성 | 장애를 견디고 오류를 최소화 |
| 개인정보 보호/보안 | 사용자 개인정보 보호, PII 비노출 |
| 거버넌스 | 산업 표준/모범사례 준수 및 감사, 위험 완화 |
| 투명성 | 모델 기능·제한사항·잠재 위험에 대한 명확한 정보 제공(사용자가 AI와 상호작용 중임을 인지) |

#### 4.1.2 편향과 분산
- 공정성은 여러 그룹 간 결과의 편향/분산으로 측정. **인구통계적 격차**: 연령·인종·성별 등에 따른 불평등 결과.
- **과대적합**: 훈련 데이터가 현실을 대표하지 못할 때 → 유사 입력에만 잘 작동, 소수 그룹이 부정적 결과 경험.
- **과소적합**: 특정 그룹 관련 훈련 데이터 부족 시 성능 저하.
- **클래스 불균형 예시**: 훈련 데이터 여성 32.4% / 남성 67.6% → 남성 추론 성능 우수, 여성 데이터 과대적합 위험(오류율 상승, 예: 질병 오진).
- **레이블 불균형 예시**: 훈련 데이터가 중년층의 대출을 더 높은 이자율로 승인하는 원치 않는 패턴을 보이는 경우(한 클래스의 긍정적 결과를 다른 클래스보다 선호).
- **대표성 부족 예시**: 주로 중년층 데이터로 훈련된 모델은 청년층·노년층을 대상으로 예측할 때 정확도가 떨어질 수 있음.
- 훈련 데이터의 편향 = 출력의 편향 → **윤리적 데이터셋이 책임감 있는 AI의 기반**.

**윤리적 데이터셋 특성**
- 포용성(다양한 인구/관점/경험), 다양성(광범위 속성/변수), 큐레이션(품질·무결성 검증), 균형(그룹 동등 표현), 개인정보 보호(규제 준수), 동의/투명성, 정기 감사.

**모델 선택 시 윤리적 고려사항**
- 환경 영향(탄소 발자국·에너지 소비 평가), **지속 가능성**(기존 작업 재사용으로 훈련량↓), 투명성, **책임성**(결과·의사결정 책임 한계 설정), 이해관계자 참여(다양한 관점 포함).

#### 4.1.3 SageMaker Clarify – 편향 탐지·설명 가능성
- 데이터 준비 중/훈련 후/배포된 모델에서 편향 탐지(특정 속성 검사).
- 모델을 **블랙박스**로 취급해 입력·출력 관찰로 특성 상대적 중요도 결정(딥러닝, 비정형 데이터의 CV/NLP 모델도 설명 가능).
- 프로세스: SageMaker Clarify 처리 컨테이너 → S3에서 데이터·구성 로드 → 모델 컨테이너에 요청·예측 검색 → 분석 결과(편향 지표+특성 기여도 JSON, 비주얼 보고서) S3 저장.

**편향 지표 (예시: 대출/입학)**

| 지표 | 정의 |
|---|---|
| 인구통계적 격차 | 특정 클래스의 거부 비율이 허용 비율보다 과도하게 큰지 여부(예: 여성 불합격 46% vs 합격 32%) |
| 예측 긍정 비율 차이 | 모델의 클래스별 긍정 예측 차이 (훈련 데이터 레이블 불균형과 비교) |
| 특이도 | 부정 결과를 정확히 예측하는 빈도(그룹 간 차이=편향) |
| 재현율 차이 | 클래스 간 재현율(TPR) 차이 |
| 정확도 차이 | 클래스 간 예측 정확도 차이 |
| 처리 평등 | 거짓부정/거짓긍정 비율의 클래스 간 차이(정확도는 같아도 오류 유형이 다를 수 있음) |

#### 4.1.4 생성형 AI 위험 사례
- **환각**: 2023년 뉴욕 법원 사건 — 변호사가 생성형 AI의 가짜 판례를 인용한 변론서 제출 → 소송 기각, 제재·벌금.
- **저작권**: AI 생성물 자체는 저작권 불가하나, 훈련 데이터(저작권/특허/상표 보호 대상)가 출력에 포함될 위험. 예: 2023년 **Getty Images vs Stable Diffusion 개발사**(1,200만+ 이미지·캡션·메타데이터 무단 사용 소송).
- **차별**: 미국 평등고용기회위원회(EEOC)가 55세 이상 여성/60세 이상 남성 자동 거부한 AI 채용 프로그램 사용 3개 회사 고소.
- **유해 콘텐츠**: 공격적/외설적 콘텐츠 생성 → 정신적·정서적 피해, 폭력 성향 증가 가능성.
- **데이터 프라이버시**: 민감 데이터(PII, 지적재산, 영업비밀, 의료기록) 유출 위험 — 훈련 데이터 또는 사용자 프롬프트 통해 유입. FM은 훈련/확인한 데이터를 "잊게" 할 수 없음.

#### 4.1.5 Amazon Bedrock 가드레일
- 부적절한 콘텐츠 필터/차단: 증오, 모욕, 성적 콘텐츠, 폭력 등 임계값 설정. 특정 주제 전체 차단(자연어 설명).
- 프롬프트가 가드레일 통과 못하면 모델에 전달 안 되고 구성된 위반 응답 반환. 응답 측에도 가드레일 적용 가능(양방향).

#### 4.1.6 SageMaker Clarify – LLM 평가 작업
- 4가지 태스크: 텍스트 생성, 텍스트 분류, Q&A, 텍스트 요약.
- 5가지 평가 차원:
  1. **프롬프트 고정관념(stereotyping)**: 인종/성별/성적취향/종교/연령/국적/장애/외모/사회경제적 지위 편향 확률
  2. **유해성**: 성적 언급, 무례/비합리/증오/공격적 댓글, 욕설, 모욕, 위협 등
  3. **사실적 지식**: 응답의 진실성
  4. **시맨틱 견고성**: 오타/대문자 변경/공백 추가삭제에 따른 출력 변화 여부
  5. **정확도**: 예상 응답과 비교(분류/요약 정확성)
- 빌트인 프롬프트 데이터셋 또는 직접 제공 가능, 인적 피드백(직원/주제전문가) 활용 가능. Bedrock 콘솔에서도 동일 기능 사용 가능.

### 4.2 투명하고 설명 가능한 모델의 중요도

#### 4.2.1 투명성의 두 척도
- **해석 가능성**: 모델 작동 방식·출력 이유를 이해할 수 있는 정도. 선형회귀(기울기/절편), 의사결정트리처럼 단순한 알고리즘일수록 높음. 신경망(뇌 모사)은 해석 어려움.
- **설명 가능성**: 방법을 정확히 몰라도 모델을 관찰(입력→출력)해 설명 가능 — 모델을 블랙박스로 취급, 모델 독립적 접근. 실무 목표(예: 스팸 플래그/대출 거부 이유)엔 이 수준으로 충분한 경우가 많음.
- 규제/비즈니스 요구가 완전 투명성을 요구하면 해석 가능한 모델(선형회귀, 의사결정트리 등) 선택.

#### 4.2.2 트레이드오프
- **성능 vs 해석 가능성**: 복잡도 낮은 모델(해석 쉬움) → 기능·성능 제한(예: 단어별 치환 번역 vs 신경망 유창한 번역).
- **안전성 vs 투명성**: 투명한 모델은 해커가 내부 메커니즘을 알아 취약점 발견·공격에 더 취약. 불투명 모델은 공격자가 관찰 가능한 정보로 학습 범위가 제한됨. 모델 아티팩트 보호 중요.
- 독점 알고리즘 노출↑ → 리버스 엔지니어링 용이. 투명성 유지 + 고객 데이터 프라이버시 보장의 어려움(훈련 데이터 세부사항 공유 필요성과 상충).

#### 4.2.3 투명성/설명 가능성 지원 도구
- **오픈소스 SW**(예: GitHub): 협업 개발, 투명성 극대화, 공정성 확신, 다양성↑·편향↓, 문제 발견 가능성↑. 단, 일부 기업은 안전 우려로 사용 금지·독점 개발 선호.
- AWS 완전 훈련 모델(API만 상호작용, 직접 접근 불가) → AWS가 책임감 있는 AI 처리 방식에 투명해야 함.
- **AI 서비스 카드**: 의도한 사용 사례·제한사항·책임 있는 AI 설계 선택·배포/성능 최적화 모범사례 문서(예: Rekognition 얼굴 일치, Textract ID 분석, Comprehend PII 탐지, Bedrock Titan Text).
- **SageMaker Model Cards**: 사용자 생성 모델의 설계~평가 수명주기 문서화(SageMaker 훈련 세부정보 자동 채움).
- **SageMaker Clarify**: **Shapley 값** 기반 특성 기여도(각 특성의 예측 기여도), **부분 종속성 도표**(특성 값에 따른 예측 변화).

#### 4.2.4 인간 중심 AI
- 인간의 요구/가치를 우선시하는 설계, 학제 간 협업(심리학자·윤리학자·도메인 전문가), 사용자 개발 프로세스 참여. 목표: 인간 능력 **대체가 아닌 향상**.
- **Amazon Augmented AI(A2I)**: AWS AI 서비스/커스텀 모델 추론에 인간 검토 통합. 신뢰도 낮은 추론을 인간 검토자에게 전달 → 피드백을 훈련 데이터에 반영해 재훈련. 무작위 예측 감사도 가능. 조직 자체 검토자 풀 또는 Mechanical Turk 사용. 예: Rekognition의 노골적 콘텐츠 저신뢰 예측 인간 검토.
- **RLHF**: 진실되고 무해하며 유용한 콘텐츠 생성을 위한 산업 표준. 보상 모델을 별도 훈련(동일 프롬프트에 대한 여러 응답을 사람이 선호도 표시 → 훈련 데이터) → LLM이 보상 모델로 최대 보상 응답 구체화. **SageMaker Ground Truth**로 RLHF용 인간 선호도 가장 쉽게 수집(응답 순위 매기기).
