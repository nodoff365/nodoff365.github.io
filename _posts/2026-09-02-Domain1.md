### 1.1 기본 AI/ML/DL 개념과 용어

#### 1.1.1 AI (인공지능)
- 정의: 학습·창조·이미지 인식 등 인간 지능과 관련된 인지 문제를 해결하는 컴퓨터 과학 분야. 목표는 데이터에서 의미를 도출하는 자체 학습 시스템. 예: **Alexa, ChatGPT**(질문에 의미 있게 응답, 텍스트/이미지 등 독창적 콘텐츠 생성).
- 특징: 대량 데이터 실시간 처리(사기 탐지), 반복 업무 자동화, 패턴 인식/추세 예측 → 스마트한 의사결정.
- 산업 적용 예: 의료(엑스레이 판독), CDC(팬데믹 예측), Koch Industries(컴퓨터 비전 조립라인 모니터링·예측 정비), 고객 지원 챗봇, Discovery(시청 이력 기반 추천), 택시 배차 예측, MasterCard(사기 탐지), HR 이력서 매칭, 프로모션 타겟팅/스팸 방지, TicketTek(맞춤 이벤트 추천).
- **회귀 분석/시계열 추론**: 과거 데이터(시계열)로 미래 값 예측. 예: 매장이 특정 날짜에 필요한 영업사원 수를 과거 패턴으로 예측. 추론은 확률적 결과(경험적 추측).
- **이상 탐지 예**: 콜센터 통화량이 예측 범위를 벗어나면(앱 오프라인 전환 등) AI가 감지해 IT 부서에 알림.
- **컴퓨터 비전 예**: 표면 긁힌 자국에 빨간 상자 표시, 회로기판의 콘덴서 누락 식별.
- **기계 번역 예**: 고객지원 채팅에서 스페인어↔영어 실시간 번역.
- **NLP 예**: Alexa, 호텔 예약 챗봇(필요 정보 안내).
- **생성형 AI 예**: Amazon Bedrock에 "이 가사로 노래를 만들어줘" 프롬프트 입력 → 2절+코러스+브릿지+아웃트로 완성된 노래 가사 생성.

#### 1.1.2 ML (기계 학습)
- 데이터+알고리즘으로 인간 학습 방식을 모방. 특성(feature, 표의 열/이미지 픽셀)으로 훈련 → 내부 파라미터 조정 → 추론(새 데이터에 대한 출력 생성, 확률적 결과). 예: 온라인 쇼핑 고객을 위한 제품 추천.
- **데이터 유형**

  | 유형 | 특징 | 예 | 저장/서비스 |
  |---|---|---|---|
  | 정형 | 테이블 행/열 | CSV | RDS, Redshift(SQL), 훈련용 S3 export |
  | 반정형 | 속성 다르거나 누락 가능 | JSON(키-값) | DynamoDB, DocumentDB(MongoDB 호환) |
  | 비정형 | 특정 모델 없음 | 이미지·비디오·SNS 게시물 | S3 객체 스토리지, 토큰화로 특성 추출 |
  | 시계열 | 타임스탬프+순차 저장 | 마이크로서비스 성능지표(메모리/CPU/TPS) | 사전 확장 등에 사용, S3 저장 |

- **선형 회귀 예**: h=mw+b (키=몸무게 함수) → 훈련 중 m(기울기)·b(절편)을 오차 최소화 방향으로 반복 조정.
- **모델 아티팩트**: 훈련된 파라미터+모델 정의+메타데이터(보통 S3 저장) → 추론 코드와 패키징 → 배포 가능한 모델.
- **호스팅 방식**
  - 실시간 추론: 영구 엔드포인트, 저지연·높은 처리량 필요 시.
  - 배치: 대량 데이터 오프라인 처리, 컴퓨팅은 처리 시에만 실행(비용 효율적).

**ML 유형**

| 유형 | 정의 | 예/특징 |
|---|---|---|
| 지도 학습 | 레이블 있는 데이터로 훈련 | 어류/비어류 이미지 분류. 레이블링 과제 → SageMaker Ground Truth(+Amazon Mechanical Turk 크라우드소싱) |
| 비지도 학습 | 레이블 없음, 패턴/클러스터 발견 | 네트워크 트래픽 클러스터링, 센서 이상 탐지 |
| 강화 학습(RL) | 에이전트가 환경에서 액션→보상 최대화, 시행착오 | AWS DeepRacer(자동차=에이전트, 트랙=환경) |

- 비지도학습 vs RL: 둘 다 레이블 없이 작동하지만 RL은 미리 정해진 목표가 있고 지속적 탐색·검증으로 목표 확률을 높임.

**모델 품질 이슈**
- **과대적합(overfitting)**: 훈련 데이터엔 강하지만 새 데이터에 약함 → 해결: 더 다양한 데이터로 훈련(너무 오래 훈련해도 발생, 노이즈 과대 강조).
- **과소적합(underfitting)**: 입력-출력 간 의미 있는 관계를 못 찾음(훈련 부족/데이터 부족).
- **편향(bias)**: 여러 그룹 간 성능 차이. 예: 대출 모델이 훈련 데이터에 없는 특정 인구(위스콘신 25세 여성)를 부당하게 거부. 해결: 특성 가중치 조정(성별 제거 등), 공정성 제약조건 사전 식별, 지속적 평가.

#### 1.1.3 딥러닝(DL)
- 신경망(노드=뉴런 모사) 구조. 입력층-은닉층(들)-출력층, 노드별 자율 가중치, 순방향 정보 흐름, 오차 역전파로 가중치 조정.
- 이미지 분류·NLP에 강함(특성을 자체 추출 → 레이블링 인력 부담은 여전히 큼: 수백만 장 필요).
- 클라우드 컴퓨팅 저비용화 이후 컴퓨터 비전의 표준이 됨. 비용/인프라는 기존 ML보다 높음.
- 기존 ML vs DL: 정형/레이블 데이터엔 기존 ML(분류·추천, 예: 통신사 이탈 예측)이 우수·효율적; 비정형 데이터(이미지·비디오·텍스트, 감정 분석 등)엔 DL이 적합.
- **생성형 AI 도입부**: 트랜스포머 신경망(프롬프트→응답, 병렬 처리로 훈련 가속), 대규모 언어 모델(수십억 파라미터) - 번역·창작·코드 작성 가능. 예: Amazon Bedrock, partyrock.aws(무료 실습).

### 1.2 AI의 실제 사용 사례

#### 1.2.1 AI가 적합한 경우 / 부적합한 경우
- 적합: 24시간 무중단 작동, 반복 업무 대체, 대량 데이터 분석, 패턴 편차 탐지(사기), 수요 예측.
- 부적합/주의:
  - **비용**: 훈련·재훈련 비용이 절감 효과보다 크면 진행하지 않음.
  - **해석 가능성(interpretability)**: 복잡한 신경망은 예측 근거 설명이 어려움 → 완전한 투명성이 필요하면 단순 모델 또는 규칙 기반 시스템(결정론적) 선택.
  - **결정론적 vs 확률적**: 규칙 기반=항상 동일 입력→동일 출력(결정론적); ML 모델=확률적(같은 입력이라도 다른 결과 가능) → 결정성 필요시 규칙 기반이 유리.

<br>

#### 1.2.2 ML 문제 유형
- **지도 학습**: 특성(입력)+레이블(대상값)
  - 분류(범주형 대상): 이진 분류(질병 유무, 어류/비어류), 다중 분류(문서 주제, 해양생물 종류)
  - 회귀(연속형 대상): 선형 회귀(단순/다중, 예: 몸무게→키, 주택 특성→가격), 로지스틱 회귀(0~1 확률, 예: BMI 등→심장병 예측, 사기 여부 예측)
- **비지도 학습**: 레이블 없는 특성만 존재
  - 클러스터링: 구매내역/클릭스트림 기반 고객 그룹화
  - 이상 탐지: 고장 센서, 의료 오류 탐지

<br>

- **Rekognition 얼굴 인식**: 직원 배지·운전면허증 같은 참조 이미지와 비교해 신원 확인. 데모에서 참조 이미지로 다른 사진 속 인물을 **99.8% 신뢰도**로 일치 판정, 다른 얼굴은 "일치하지 않음"으로 구분. 도로 표지판처럼 보이는 텍스트에도 레이블 추가 가능.

- **Kendra**: "Echo Plus를 네트워크에 어떻게 연결하나요?" 같은 자연어 질문을 이해하고 지능적으로 응답.
- **Personalize**: 전자상거래 앱의 "당신이 좋아할 만한 제품" 섹션처럼 관심 있을 고객에게 맞춤 상품 추천.
- **Bedrock**: Amazon Titan Image Generator로 텍스트 프롬프트에 대한 응답 이미지 생성.

### 1.3 ML 개발 수명주기

#### 1.3.1 파이프라인 개요
1. 비즈니스 목표 정의

2. 데이터 수집/준비

3. 모델 훈련/조정/평가

4. 배포

5. 모니터링

배포 후에도 반복되는 **수명주기**다.

<br>

#### 1.3.2 비즈니스 목표 정의
- 명확한 성공 기준 필요(측정 가능한 비즈니스 가치), 이해관계자 합의.
- 가장 간단한 솔루션부터 검토 → 비용편익분석.
- 옵션 우선순위: **AWS AI 서비스**(완전 훈련·종량제) → **기존 모델 활용/미세조정**(Bedrock 전이학습, SageMaker JumpStart 사전훈련 모델) → **처음부터 훈련**(가장 어렵고 비쌈, 보안/규정준수 책임 최대).

<br>

#### 1.3.3 데이터 수집 및 준비
- 데이터 소스/스트리밍 여부 파악, ETL(추출·변환·로드) 구성, 레이블링 방법 결정.
- 탐색적 데이터 분석(EDA), 데이터 랭글링, 결측/이상치 처리, PII 마스킹/제거.
- 데이터 분할 권장: **훈련 80% / 평가 10% / 최종 테스트 10%**.
- 특성 선택/결합으로 차원 축소 → 메모리·컴퓨팅 절감.

**관련 AWS 서비스**

| 서비스 | 역할 |
|---|---|
| AWS Glue | 완전관리형 ETL, Data Catalog(메타데이터: 위치·스키마), Crawler로 자동 스키마 탐지 |
| AWS Glue DataBrew | 코드 없이 데이터 정리/정규화, 250+ 빌트인 변환, 레시피 저장/재사용, 데이터 품질 프로파일링 |
| SageMaker Ground Truth | 고품질 레이블 데이터셋 구축, Active Learning(자동 레이블+나머지 인간에게), Mechanical Turk(50만+ 계약자) 또는 내부 인력 활용 |
| Amazon SageMaker Canvas | 코드 없는 데이터 준비·특성화, Data Wrangler 데이터 선택 도구, 300+ 빌트인 변환 |
| Amazon SageMaker Feature Store | 특성/메타데이터 중앙 저장소, 재사용·공유 가속 |

<br>

#### 1.3.4 모델 훈련·조정·평가
- 훈련: 파라미터(가중치) 반복 업데이트, 오차를 낮추는 방향으로 조정, 정의된 반복 횟수 또는 오차 변화 임계값에서 중지.
- 여러 알고리즘/설정 병렬 실행("실행 실험")으로 최적 조합 탐색. **하이퍼파라미터**(신경망 계층 수 등)는 훈련 전 설정하는 외부 파라미터.
- SageMaker 훈련 작업: S3(훈련 데이터) URL 지정, 컴퓨팅 리소스+출력 S3 버킷 지정, ECR의 Docker 컨테이너(알고리즘) 지정, 하이퍼파라미터 설정.
- **Amazon SageMaker 실험**: 다수 훈련 실행 생성/관리/비교, 성능 지표로 최고 모델 식별.
- **Amazon SageMaker 자동 모델 튜닝(AMT/하이퍼파라미터 튜닝)**: 지정한 알고리즘/하이퍼파라미터 범위 내에서 다수 훈련 실행 → 지표(예: AUC) 최적 조합 탐색, 완료 기준(개선 없는 작업 수 등) 지정.

<br>

#### 1.3.5 배포
- **배치**: 대량 추론, 결과 대기 가능, 비용 효율적(예: 야간 재고 예측).
- **실시간**: REST API(클라이언트 POST 요청 → 엔드포인트 → 컴퓨팅 → 응답). 예: API Gateway + Lambda.
- 인프라 옵션(직접 관리 필요): AWS Batch, ECS, EKS, Lambda, EC2.
- **Amazon SageMaker 완전관리형 호스팅**(운영 오버헤드 감소) 4가지 추론 옵션:

  | 옵션 | 특징 |
  |---|---|
  | 실시간 | 지속적 완전관리형 엔드포인트 REST API, 상시 트래픽 처리 |
  | 배치 변환 | 대규모(GB급) 오프라인 추론, 영구 엔드포인트 불필요 |
  | 비동기식 | 대용량 페이로드/긴 처리시간, 요청 대기열, 무요청 시 0으로 축소(무과금) |
  | 서버리스 | Lambda 기반, 프로비저닝/스케일링 불필요, 트래픽 간헐적일 때 유리 |

<br>

#### 1.3.6 모니터링
- 데이터 품질/모델 품질/편향으로 성능 저하 가능 → 데이터 캡처, 훈련 세트와 비교, 규칙 정의, 알림.
- **데이터 드리프트**: 입력 분포 변화 / **개념 드리프트**: 목표 변수 속성 변화. 둘 다 성능 저하 유발.
- **Amazon SageMaker Model Monitor**: 엔드포인트 데이터 수집, 기준 대비 변경 탐지(기본/사용자 규칙), 결과는 SageMaker Studio + CloudWatch(경보→재훈련 자동화 가능).

<br>

#### 1.3.7 MLOps
- 소프트웨어 엔지니어링 모범사례를 ML에 적용: 자동화, 테스트/평가, 인시던트 자동 대응.
- 원칙: 인프라 코드화(IaC), 버전 관리(훈련 데이터 포함), 배포 모니터링+재훈련 자동화.
- 이점: 생산성/자동화, 반복성, 감사 가능성(계보 추적), 데이터·모델 품질 향상.
- **Amazon SageMaker Pipelines**: SageMaker 작업 오케스트레이션, 재현 가능한 ML 파이프라인(SDK for Python 또는 JSON), 조건부 브랜치 지원, 계보 추적, SageMaker Studio에서 확인 가능(예: 전복 나이 추론 파이프라인).
- 기타 리포지토리/오케스트레이션: **AWS CodeCommit**(소스코드), **SageMaker Feature Store**(특성), **SageMaker Model Registry**(모델+기록), **AWS Step Functions**(드래그앤드롭 서버리스 워크플로), **Amazon Managed Workflows for Apache Airflow(MWAA)**.

#### 1.3.8 평가 지표

**혼동 행렬 기반 (분류)**
- 참긍정(TP)/참부정(TN)/거짓긍정(FP)/거짓부정(FN)
- 예시(100개 테스트, 어류 모델): 정확도 0.65, 정밀도 0.55, 재현율 0.625 (불균형 데이터셋에선 정확도만 90%를 보일 수 있어 부적절)

| 지표 | 공식 | 용도 |
|---|---|---|
| 정확도(Accuracy) | (TP+TN)/전체 | 데이터 균형일 때 유효 |
| 정밀도(Precision) | TP/(TP+FP) | 거짓긍정 최소화(예: 스팸 아닌 메일이 스팸 처리되면 안됨) |
| 재현율(Recall, TPR, 민감도) | TP/(TP+FN) | 거짓부정 최소화(예: 질병 놓치면 안됨) |
| F1 점수 | 정밀도·재현율 조화평균 | 둘 다 중요할 때 절충 |
| 거짓긍정비율(FPR) | FP/(FP+TN) | — |
| 참부정비율 | TN/(FP+TN) | — |
| AUC(ROC 곡선 아래 면적) | — | 확률 기반 이진분류 비교, 1=완벽, 0.5=랜덤 수준 |

**회귀 평가 지표**
- **MSE**(평균제곱오차): (예측-실제)² 평균, 이상치 강조
- **RMSE**: MSE의 제곱근, 단위가 종속변수와 일치해 해석 쉬움
- **MAE**(평균절대오차): 오차 절대값 평균, 이상치 영향 덜함
