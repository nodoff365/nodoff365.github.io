### 1.1 AI 시스템 보안

#### 1.1.1 공동 책임 모델
- **AWS 책임(클라우드 자체)**: 데이터센터, 네트워킹, 물리적 하드웨어, 리전/가용영역/글로벌 인프라, 물리적 서버·호스트 OS·가상화 계층·네트워킹 구성요소.
- **고객 책임(클라우드 내 보안)**: 액세스 제한, 암호화, 모범사례 준수, 서비스/애플리케이션 올바른 구성. 책임 수준은 서비스 유형에 따라 다름(예: EC2 배포 시 OS·패치·크기조정·앱 보안은 고객 책임; SageMaker 서버리스 추론은 완전관리형이라 고객 관리 최소화).

<br>

#### 1.1.2 IAM (Identity and Access Management)
- AWS 계정/리소스 액세스 관리·보호 웹서비스. 글로벌 리소스(리전 무관, 단 권한을 특정 리전으로 제한 가능). 추가 비용 없음(연결된 서비스 사용 시에만 과금).
- **루트 사용자**: 계정 생성 시 완전 액세스 권한(제한 불가) → 강력한 암호+MFA 필수, 액세스 키 미공유, 일상 작업엔 미사용(청구 관리 등 특정 작업 예외).
- **단일 요소 인증**의 취약점(암호 유출 시 계정 탈취 위험) → 악의적 행위자가 소셜 엔지니어링·봇·스크립트로 암호를 알아내면 중요 데이터 삭제나 비용이 많이 드는 가상화폐 채굴 작업 가동 등의 피해가 가능 → **MFA**로 보완.
- **IAM 사용자**: 사용자별 개별 생성(자격증명 공유 금지), 기본적으로 권한 없음(명시적 부여 필요).
- **IAM 정책**: 권한 허용/거부 JSON 문서, **최소 권한 원칙** 적용(예: 사용자가 EC2 인스턴스를 시작·중지할 수 있게만 허용하는 JSON 정책).
- **IAM 그룹**: 사용자 모음, 정책을 그룹에 할당해 일괄 권한 부여(예: **3,000명**의 사용자가 있는 계정에서 개별 관리는 어려우므로 작업 기능별로 구성 — 개발자/QA/관리자 그룹). 그룹은 그룹에 속할 수 없음.
- **IAM 역할**: 임시 자격증명(세션 기반, 자동 만료) — 장기 자격증명 대신 권장. 예: 개발자가 AWS 자격증명을 소프트웨어에 포함시켰다가 코드 공유 전 삭제를 잊어버리는 위험을 방지. IAM 사용자/AWS 서비스/외부 자격증명 제공자가 사용 가능, 신뢰 정책으로 역할 수임자 결정.
- **자격증명 기반 정책** vs **리소스 기반 정책**(예: S3 버킷 정책) — 둘 중 하나라도 허용하면 허용되나, 명시적 거부가 우선.
- **ID 페더레이션**: Active Directory 등 외부 IdP로 인증 → 임시 자격증명 발급. **AWS IAM Identity Center**: 인력 사용자 관리, 여러 계정 권한을 중앙에서 관리(그룹 수준 권한 세트 할당), 역할 기반 임시 권한 부여 — IAM보다 권장되는 방식.
- **AWS CloudTrail**: API 호출/관련 이벤트 캡처 → 지정 S3 버킷에 로그 전달. SageMaker와 통합(엔드포인트 호출 제외 대부분 API 캡처) — 요청 IP/사용자/시간 확인 가능.

<br>

#### 1.1.3 데이터 접근 보호
- **Amazon S3 퍼블릭 액세스 차단**: 버킷/계정 수준에서 퍼블릭 액세스 차단(버킷 정책/ACL의 퍼블릭 권한 재정의).
- **Amazon SageMaker Role Manager**: IAM 정책 직접 작성 없이 ML 활동 권한 부여 역할 생성. 3가지 페르소나: **데이터 과학자**(일반 ML 개발/실험), **MLOps**(모델·파이프라인·실험·엔드포인트 관리, S3 데이터 접근 불필요), **SageMaker 컴퓨팅**(훈련/추론 리소스 작업용).

<br>

#### 1.1.4 암호화
- 모든 AWS 서비스: 저장 시(at rest) + 전송 중(in transit) 암호화 지원.
- 클라이언트 측(전송 전 암호화) vs 서버 측(서비스에서 암호화, 구현 간편). 일부 서비스(S3, DynamoDB, SageMaker)는 기본적으로 데이터 암호화(서비스 소유 키 사용).
- **AWS KMS**: 계정 소유 암호화 키 생성/관리/사용, IAM 정책으로 키 사용 제어(추가 보호 계층 — 읽기 권한 있어도 KMS 키 권한 없으면 복호화 불가). 고객 관리형 키로 키 정책·교체·사용중지 제어.
- 모든 서비스 엔드포인트가 TLS 지원(보안 HTTPS 연결).
- SageMaker 분산 훈련: 노드 간 트래픽은 기본 비암호화(옵션으로 암호화 가능, 단 딥러닝 알고리즘 훈련시간 증가 가능).
- **Amazon Macie**: S3 버킷 지속 평가(크기/상태/퍼블릭·프라이빗/공유/암호화 상태 인벤토리), ML+패턴 매칭으로 PII 등 민감 데이터 식별·알림(워크플로 자동화 연계 가능). PII는 수집·변환 시점에 훈련 데이터에서 제거 필요.

<br>

#### 1.1.5 네트워크 보안
- **VPC**: 자체 프라이빗 네트워크 구성. SageMaker Studio/노트북 인스턴스는 SageMaker 관리 VPC에서 실행(기본 인터넷 액세스 있음 — 악성코드 다운로드 위험).
- 자체 VPC 지정 시 보안 그룹/네트워크 ACL/네트워크 방화벽으로 트래픽 제어 가능. "VPC만" 지정으로 인터넷 액세스 차단 가능.
- **VPC 인터페이스 엔드포인트(AWS PrivateLink)**: 프라이빗 네트워크로만 트래픽 이동(VPC 전용 모드).

<br>

#### 1.1.6 AI 시스템 취약점 & 대응

| 취약점 | 설명 |
|---|---|
| 데이터 포이즈닝 | 훈련 데이터에 악의적 데이터 주입해 예측 조작(예: 사기 거래를 정상으로 라벨링) |
| 적대적 입력 | 입력 데이터를 미묘하게 조작해 오분류 유도(예: 얼굴인식 회피 이미지) |
| 모델 반전 | 모델 출력 반복 관찰로 훈련 데이터 역추론(예: 얼굴 이미지 반복 입력으로 직원 이미지 재구성) |
| 리버스 엔지니어링 | 입출력 페어 다수 확보해 유사 모델 재훈련(모델 정보 많을수록 정확도↑) |
| 프롬프트 인젝션 | 프롬프트 내 악의적 명령으로 LLM 출력 조작(민감 정보 탈취 등) |

- 완화책: 최소 권한 원칙, 퍼블릭 액세스 차단, 데이터/아티팩트 암호화, 모델 접근 제한, 입력 데이터 검증(비정상 패턴 탐지, 프롬프트 공격 탐지 학습), 불필요한 출력 정보 제한, 적대적 입력으로 모델 훈련, 새 데이터로 자주 재훈련(별도 검증셋 보관), 데이터 정기 스캔/이상 탐지, 예측 이상 발생 시 원인(데이터 품질 vs 공격) 조사.
- **Amazon SageMaker Model Monitor**: 프로덕션 모델 품질 실시간 모니터링(데이터 드리프트/이상 자동 알림), 데이터 품질/모델 품질 모니터링(SageMaker Studio + Amazon CloudWatch 통합, 임계값 위반 시 알림). 데이터 캡처(추론 입출력) → 기준 데이터셋(보통 훈련 데이터) 대비 통계 비교 → 모니터링 작업 예약.

### 1.2 AI 시스템 거버넌스 및 규정 준수

#### 1.2.1 규정 준수 공동 책임
- AWS: 물리적 데이터센터/인프라 보호. 고객: 클라우드 내 워크로드 보호.
- AWS는 데이터센터 운영·기술·보안 관련 자격증/증명 유지, 서드파티 감사 → **AWS Artifact**를 통해 감사 보고서 제공(고객이 제어 상속 → 감사 범위 축소).
- **SOC 2**: 보안·가용성·처리 무결성·기밀성·개인정보보호 관련 제어 보고(AWS SOC 2 보고서를 시작점으로 자체 인증 가능).
- **ISO 27001**: 국제 보안 관리 표준(포괄적 보안 제어).
- **고객 규정 준수 센터**: 규정 준수 사례·백서·보안 감사 체크리스트·감사자 학습 경로 제공.

<br>

#### 1.2.2 AI 관련 규정/프레임워크

| 규정/프레임워크 | 내용 |
|---|---|
| ISO 42001 / ISO 23894 (2023) | AI 시스템 위험 평가·관리 메커니즘, 책임감 있는 AI 프레임워크(법적 요구 아님) |
| EU AI Act | AI 애플리케이션 3단계 위험 분류: ① 용납불가 위험(전면 금지 — 소셜 채점, 무단 얼굴인식DB, 감정 추론 등) ② 고위험(법적 요구사항 적용 — 이력서 스캐닝 등, 대부분 AI가 여기 해당 → 위험관리시스템·데이터 거버넌스·문서화 필요) ③ 비규제(대부분). GDPR처럼 글로벌 표준화 가능성 |
| NIST AI RMF | 신뢰할 수 있는 AI 개발 지침(자발적). 4개 기능: **거버넌스, 매핑, 측정, 관리**. 위험 = 발생 가능도 × 결과 심각도. **내재적 위험**(완화 전) → 보안 제어/모니터링으로 완화 → **잔존 위험**(완화 후 남는 위험) |
| Algorithmic Accountability Act | (미 의회 심의 중) AI 시스템 영향평가 의무화, 투명성 확보, 불공정/설명 불가 결과로부터 소비자 보호(대출 거부 사유 등 알 권리) |

**NIST 위험 평가 절차**
1. AI 사용 사례 및 이해관계자 식별

2. 잠재적 유해 이벤트 식별 → 위험 행렬로 위험도 결정

3. 보안 제어/모니터링으로 내재적 위험 완화

4. 잔존 위험 산정

5. 가장 높은 잔존 위험 기준으로 전체 위험 수준 요약

**편향 제거·설명 가능성 원칙**
- 인종/성별/성정체성/종교/정치성향/거주지 등 개인 속성이 결과에 부적절하게 영향 미치지 않도록 함.
- **SageMaker Clarify**: 변수의 모델 동작 영향 이해, 편향/특성 기여도 드리프트 모니터링.

#### 1.2.3 AWS 규정 준수 지원 서비스

| 서비스 | 기능 |
|---|---|
| AWS Audit Manager | 규정 준수 요구사항을 AWS 사용 데이터에 매핑, 증거 수집·평가 보고서 생성(기본/자체 프레임워크, 생성형 AI 모범사례·SOC2 프레임워크 포함) |
| Bedrock Guardrails | 증오/모욕/성적/폭력 콘텐츠 필터(임계값 구성), 자연어로 차단 주제 정의, PII 탐지·거부/수정, 프롬프트/응답별 차단 메시지 설정. 예: 전자상거래 사이트 어시스턴트가 증오 발언·모욕을 쓰지 않도록 필터링, 모델의 투자 조언 제공을 차단 주제로 추가하고 응답 예시로 "죄송하지만 해당 주제는 저희 전문 분야를 벗어납니다." 설정 |
| AWS Config | 리소스 구성 인벤토리·변경 이력(구성 기록 스냅샷), 규칙 위반 시 Systems Manager Automation으로 자동 수정. **적합성 팩**(규칙+수정 묶음, 예: AI/ML 운영 모범사례, SageMaker 보안 모범사례) |
| Amazon Inspector | 애플리케이션/컨테이너/EC2 수준 취약점 스캔(개방형 액세스, 취약 SW), 심각도별 우선순위 지정 결과 제공 |
| AWS Trusted Advisor | 비용 최적화·성능·복원력·보안·운영 우수성·서비스 한도 검사, 모범사례 편차 수정 권고 |

#### 1.2.4 데이터 거버넌스
- 정의: 데이터 가용성·유용성·무결성·보안을 관리하는 사람·프로세스·기술의 조합. 3대 요소: **큐레이션, 발견/이해, 보호**.
- **역할**

  | 역할 | 책임 |
  |---|---|
  | 데이터 소유자 | 규제/규정준수 정책 등 데이터 정책 결정(경영진), 누가 어떤 데이터 접근 가능한지 결정 |
  | 데이터 담당자(steward) | 대상 이니셔티브 데이터 세부지식 보유, 일상 업무 수행, 데이터 소유자 정책을 따름 |
  | IT | 데이터 생성/소비 시스템 관리, 담당자에게 도구·기능 제공(예: AWS 거버넌스 도구 배포) |

- **데이터 프로파일링**: 데이터 체계적 검사(문제·특성 파악). **데이터 카탈로그**: 필요한 사람이 데이터 검색·사용 가능하게 함. **데이터 계보**: 데이터 출처·이동·변환·저장 방식 추적.
- **AWS Glue DataBrew**: 코드 없는 데이터 정리, 데이터 프로파일링 작업(콘텐츠 컨텍스트·구조·관계), 데이터 품질 규칙 정의, 데이터 계보(비주얼 인터페이스로 출처·이동 경로 추적).
- **데이터 품질 관리**: 근본 원인 파악 → 담당자/사용자에게 알림·보고.
- **데이터 통합/기본 데이터 관리(MDM)**: 여러 소스 데이터 일관성 조정(예: 이메일/이름 철자 오류 조정), 담당자가 조정 규칙·계층 구조 관리.
- **AWS Glue 데이터 카탈로그**: 데이터 소스 메타데이터(형식/위치/스키마) 저장, 수동 입력 또는 Glue 크롤러로 자동 채움.
- **AWS Glue Data Quality**: 카탈로그 객체 평가, 비개발자용 품질 규칙 설정(권장 규칙+ML 이상 탐지), 규칙 통과/실패 결과 확인.
- **데이터 보안**: 역할별(고객서비스/영업 등) 자동 접근 제어, 담당자가 소유자 정책에 따라 역할기반/임시 액세스 관리.
- **규정 준수**: 데이터 소유자가 보안·법률팀과 협업해 민감 데이터 정책 결정.
- **데이터 수명주기 관리**: 접근성·비용 최적화를 위한 의도적 데이터 저장.
- **AWS Lake Formation**: S3 기반 데이터 레이크 + Glue 데이터 카탈로그로 세분화된 접근 제어(열/행/셀 수준), 여러 형식의 정형/비정형 데이터 통합, Athena/Glue/EMR/Redshift 등에서 접근 시 Lake Formation이 권한 확인.
- **Amazon S3 스토리지 등급**(비용 최적화)

  | 등급 | 용도 |
  |---|---|
  | S3 Standard | 자주 액세스 |
  | S3 Standard-IA / One Zone-IA | 드물게 액세스, 빠른 검색 필요(저장비 저렴, 검색비 높음) |
  | S3 Intelligent-Tiering | 액세스 패턴 불명/변화 시 자동 계층 이동 |
  | S3 Glacier(계열) | 거의 미접근, 장기 보존/규정 준수 아카이브, 검색 속도 옵션 다양 |

  - 수명주기 규칙: 생성 후 N일 경과 시 등급 전환/삭제 설정 가능(예: 5일 후 IA, 120일 후 Glacier Deep Archive, 5년 후 삭제).

#### 1.2.5 AI 거버넌스 전략 구현 단계
1. 책임 범위 식별(거버넌스/규정준수, 법적/개인정보, 위험관리, 보안제어 구현, 모델 복원력).

2. **생성형 AI 보안 범위 지정 행렬**: Scope 1·2(서드파티/엔터프라이즈 앱 사용, 책임 최소) ~ Scope 3·4·5(자체 AI 솔루션 구축, 데이터 위험분류/위협모델링/접근제한/보안제어/엔드포인트 복원력까지 책임). 요구사항 충족되면 낮은 Scope(완전훈련 AI서비스 → Bedrock 사전훈련+RAG → JumpStart 미세조정 순으로 검토)가 유리 — 범위 최소화로 책임도 최소화.

3. AI 거버넌스 정책 문서화 및 직원 교육(직무·접근 수준별 책임, 데이터 거버넌스/액세스 요청/모델 투명성 표준).

4. 필요한 규정준수·자격증에 따라 정책/모범사례 수립.

5. 성능·규정준수·편향 모니터링 메커니즘 정의, 임계값 기반 조치 결정.

6. 결과를 자주 검토·정책 수정(비즈니스 목표·AI 안전성 부합 유지).
