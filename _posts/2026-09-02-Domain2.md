## 개요
- Task 2.1: 생성형 AI 기본 개념 / Task 2.2: 비즈니스 문제 해결을 위한 기능·제한 / Task 2.3: 생성형 AI 애플리케이션 구축용 AWS 인프라·기술

## Task 2.1 – 생성형 AI 기본 개념

### 정의
- 생성형 AI = **딥러닝의 하위집합**. 기존 콘텐츠 분류·탐지가 아닌 **독창적 신규 콘텐츠**(텍스트·이미지·오디오·비디오·코드) 생성.
- 대량 훈련 데이터에서 패턴/표현 학습 → 유사한 결과 생성. **파운데이션 모델**(수십억 파라미터, 사전훈련) 기반. 파라미터가 많을수록 메모리↑ → 고급 태스크 가능. 그대로 사용하거나 미세조정.

### 핵심 요소: 트랜스포머
- 2017년 논문 "Attention Is All You Need"에서 소개. ChatGPT 등 다수 LLM의 기반.
- 인터넷 텍스트로 사전훈련 → 광범위 지식 기반 + 적은 데이터로 미세조정 가능.
- **핵심 개념(시험 대비)**: 프롬프트, 추론, 완성(completion), 컨텍스트 창, 토큰, 어휘, 토크나이저, 프롬프트 엔지니어링, 임베딩 계층, 인코더/디코더, 소프트맥스 출력.
- 통계·선형대수(확률 모델링, 손실함수, 행렬곱)가 계산 기반.

#### 벡터/임베딩
- **벡터**: 특정 엔터티/개념의 속성을 나타내는 숫자 순서 목록(공간 내 위치 표현, Excel 스프레드시트에 비유).
- **임베딩(벡터)**: 토큰의 고차원 표현. 텍스트·이미지 등 토큰의 시맨틱 의미를 캡처. 벡터 공간에서 가까울수록 의미적으로 유사.

#### 셀프 어텐션 & 트랜스포머 구조
- 각 입력 토큰의 쿼리·키·값 벡터 계산 → 점곱으로 어텐션 가중치 결정 → 값 벡터의 가중합이 출력.
- RNN이 어려워했던 **장거리 종속성** 포착 가능, 계산 병렬화.
- **위치 임베딩**: 시퀀스 내 토큰의 상대적 위치 인코딩(같은 토큰이 다른 위치에 있을 때 구분).
- 인코더/디코더 각각 여러 계층(계층당 2개 하위계층), 잔여 연결+계층 정규화로 훈련 용이·과대적합 방지.

### 컨텍스트 내 학습(In-context learning)
- 컨텍스트 창 내에 예제 포함 → 퓨샷/제로샷/원샷 추론으로 모델 성능 향상(프롬프트 엔지니어링 전략).

### 모델 규모와 사전훈련
- 모델이 클수록 추가 학습 없이도 작동할 가능성↑ (확장성 있는 트랜스포머 + 대량 데이터 + 강력한 컴퓨팅으로 뒷받침).
- 사전훈련: 기가~페타바이트급 비정형 텍스트, 자가지도학습으로 언어 패턴 내재화, 가중치 업데이트로 손실 최소화.
- 데이터 큐레이션(품질/편향/유해 콘텐츠 제거) 후 **토큰의 1~3%만 실제 사전훈련에 사용**됨 → 필요 원본 데이터량 추정 시 고려.

### 유니모달 vs 멀티모달 / 확산 모델
- **유니모달**: LLM(텍스트 입출력).
- **멀티모달**: 이미지·비디오·오디오 등 여러 모달리티 결합(마케팅, 이미지 캡션, 챗봇/아바타 등). 예: 이미지 캡션, 비주얼 질의응답, 텍스트-이미지 합성(DALL-E, Stable Diffusion, Midjourney).
- **확산 모델(Diffusion)**: 점진적 노이즈 프로세스를 반전(순방향 확산→역방향 확산→안정 확산). 랜덤 노이즈에서 시작해 반복적으로 노이즈 제거.
  - Stable Diffusion: 픽셀 공간 대신 저해상도 **잠재 공간(latent space)** 사용, 가우스 노이즈 인코딩+노이즈 예측기.
  - GAN·VAE 대비 장점: 더 다양·일관성 있는 고품질 출력, 안정적, 훈련 용이.
  - 확산 모델 예: Stable Diffusion(이미지), Whisper(음성인식/번역), AudioLM(오디오).
- AWS 지원: SageMaker(TensorFlow/PyTorch, 멀티모달 모듈 사전구축), 몇 줄 코드로 Stable Diffusion 등 미세조정/배포 가능.

### 생성형 AI 사용 사례
- 텍스트 생성/재작성: 예를 들어 스쿠버 다이빙 부력 장치의 설계·사양을 다룬 기술 문서를, 자격증 취득을 막 시작한 초보자를 위해 전문 용어를 줄여 다시 작성. 텍스트 요약(재무·법률·뉴스 문서).
- AWS 도구: Amazon Bedrock+Titan(텍스트/이미지/오디오), SageMaker & Amazon Q Developer(구 CodeWhisperer, 코드 생성/완성), Amazon Nimble Studio/Sumerian(3D/가상 프로덕션).
- 기타 사용 사례: 정보 추출, Q&A, 분류, 유해 콘텐츠 식별, 번역, 추천, 맞춤 마케팅, 챗봇, 검색.
- 코드 생성: 자연어 설명→코드/전체 프로그램, 코드 완성/언어 간 번역. Amazon Q Developer가 주석/기존 코드 기반 실시간 제안.
- 아키텍처: GAN, VAE, 트랜스포머 각각 장단점 상이 → 목표·데이터셋 평가 후 선택.

### 생성형 AI 프로젝트 수명주기
1. **사용 사례 식별**: 목표를 최대한 좁게 정의(범용 vs 특정 태스크) → 시간·비용 절약.
2. **실험 및 선택**: 처음부터 훈련 vs 기존 파운데이션 모델 사용.
3. **적응/정렬/증강**: 프롬프트 엔지니어링(컨텍스트 내 학습)부터 시도 → 부족하면 미세조정(지도학습) → RLHF(인간 선호 정렬)로 개선. 반복적 프로세스.
4. **평가**: 지표·벤치마크로 성능/선호 부합도 확인.
5. **배포 및 반복**: 인프라 배포, 애플리케이션 통합, 최적화.
6. **모니터링**.
- **LLM의 근본적 한계**: 환각(할루시네이션), 복잡한 추론·수학 제한 — 훈련만으로 완전 극복 어려움.

(파운데이션 모델 수명주기, 시험 가이드 기준: 데이터 선택→모델 선택→사전훈련→미세조정→평가→배포→피드백)

## Task 2.2 – 비즈니스 문제 해결을 위한 생성형 AI의 기능과 제한

### 장점
- 범용 기술(적응성·응답성·단순성) → 다양한 분야 애플리케이션(웹검색, 신용카드 사기탐지, 상품추천 등 일상 곳곳).
- 기존 AI보다 훨씬 저렴·빠르게 가치 있는 애플리케이션 구축 가능.
- 판단 기준: "10살 아이가 프롬프트 지침으로 태스크를 완수할 수 있는가?" (예: 이메일 읽고 불만 여부 판단=가능, 배경지식 없는 신제품 상세기사 작성=불가능하지만 자료 제공 시 가능).

### 제한
- LLM은 메시지 간 대화를 기억하지 못함(매번 새로운 요청과 유사) → 시간에 따른 학습 불가(단, 미세조정으로는 가능).
- **환각(할루시네이션)**: 확신에 차지만 틀린 답변 생성. 예: 당뇨병에 "탄수화물 위주 식단이 건강의 열쇠"라는 입증되지 않은 조언을 질문하면, 모델이 이를 반박하는 대신 확신에 찬 완전히 잘못된 응답을 제공할 수 있음. 권위 있는 소스로 재확인 필요.
- 유해 완성물(공격적/차별적/불법) 생성 위험.
- 핵심 인간 가치 3요소: **유용성, 정직성, 무해성** — RLHF로 정렬 개선.

### 해석 가능성(Interpretability)
- 모델 성능 vs 해석 가능성은 트레이드오프 관계.
- **내재적 분석(intrinsic)**: 입력-예측 관계가 단순한 모델에 적용(단순함 → 성능 다소 저하될 수 있음, 비선형 상호작용 캡처 못함).
- **사후 분석(post-hoc)**: 복잡한 모델(신경망 등)에 적용, 모델에 구애받지 않음(model-agnostic), 로컬(개별 데이터포인트) 또는 글로벌(전체 동작) 수준.

### LLM 평가 지표
- 기존 ML(결정적 출력) vs LLM(비결정적 출력) → 평가 난이도 차이. 예: "저는 커피를 마신다"와 "저는 커피를 마시지 않는다"라는 두 문장은 사람은 차이·유사점을 바로 이해하지만, 모델을 수백만 문장으로 훈련시킬 땐 이를 측정할 자동화·구조화된 방법이 필요함.
- **ROUGE**(Recall-Oriented Understudy for Gisting Evaluation): 사람 작성 참조 요약과 비교, 자동 생성 요약 품질 평가.
- **BLEU**(Bilingual Evaluation Understudy): 사람 번역과 비교, 기계 번역 품질 평가.

### 모델 선택 고려사항
- 모델 유형: **VAE(변이형 오토인코더), GAN(생성적 적대 신경망), 자기회귀 모델** — 각각 데이터 복잡성/품질에 따른 장단점 존재. 파운데이션 모델 수는 가파르게 증가 중(2018년 이후 주요 모델 다수 출시). 다양한 FM은 분야별로 특화됨: 예를 들어 Stability AI의 **Stable Diffusion**은 이미지 생성에 유용하고, ChatGPT는 자연어 처리에 **GPT-4** 모델을 사용.

### 비즈니스 지표
- 예: 교차 도메인 성능, 효율성, 전환율, 사용자당 평균 수익(ARPU), 정확도, 고객 평생 가치(CLTV).
- AWS ML 비즈니스 지표 분석: **Amazon Lookout for Metrics**, **Amazon Forecast**.
- 기업 통합을 위해 FM은 ERP/CRM 등 기존 시스템과 상호운용 필요, 숙련된 인력·컴퓨팅 인프라 필요.
- 출력 품질 지표: 관련성, 정확성, 일관성, 적절성 → 사용자 만족도 결정.
- 운영 효율성 지표: 태스크 완료율, 수고 감소, 오류율.
- CLTV 극대화 전략: 로열티 프로그램, 브랜드 충성도, 피드백 수집, 교차 판매, 맞춤 경험.

## Task 2.3 – 생성형 AI 애플리케이션 구축용 AWS 인프라·기술

### 전이 학습
- 처음부터 훈련하지 않고 사전훈련 모델을 새 데이터셋에서 미세조정 → 더 작은 데이터셋·짧은 훈련시간으로 정확한 모델 생성.
- **SageMaker JumpStart**: 업계 모범사례 기반 사전 구축 프로젝트(데이터셋/모델/알고리즘/솔루션) 탐색·활용.

### AWS 생성형 AI 인프라의 이점
- 접근성, 낮은 진입장벽, 효율성, 경제성, 시장 출시 속도, 비즈니스 목표 달성 능력.
- **AWS CAF-AI**(Cloud Adoption Framework for AI): AI/ML/생성형 AI 여정의 가이드/전략 토론 리소스.

### 생성형 AI 스택 보안(3계층)
| 계층 | 내용 |
|---|---|
| 하위(인프라) | LLM/FM 빌드·훈련 도구. 특수 하드웨어(**AWS Nitro System** — EC2 워크로드/데이터 무단 접근 차단, Inferentia/Trainium/P4/P5/G5/G6 인스턴스 포함) |
| 중간(플랫폼) | 모든 모델 접근 + 애플리케이션 빌드/확장 도구(ML 서비스) |
| 상위(애플리케이션) | LLM/FM 사용 코드 작성·디버그·콘텐츠 생성 등. 프롬프트 엔지니어링 대시보드, RAG 아키텍처 |

- AI 시스템 3대 핵심 구성요소: **입력, 모델, 출력** → 각각 보안 정책/표준/역할 필요.
- AI 특유 취약점: 프롬프트 인젝션, 데이터 포이즈닝, 모델 반전. 위험: 개인정보 침해, 데이터 조작, 부정 사용, 의사결정 침해.
- 대응: 암호화, 다중 인증, 지속적 모니터링, 내결함성, 프레임워크 정렬.

### 요금 모델 & 서비스
- LLM 요금: 자체 인프라 호스팅(컴퓨팅+라이선스 비용) vs **토큰 기반 과금**(정보 단위별, 확장성 유리, 인프라 투자·유지보수 불필요).
- AWS ML 스택: 글로벌 인프라(리전/엣지/가용영역) → **Amazon SageMaker**(ML 계층) → **AWS AI 서비스**(사전빌드).
- **SageMaker JumpStart**: 모델 허브, 빠른 배포·미세조정·프로덕션화, 리소스(블로그/비디오/노트북). GPU 필요, 요금 페이지 확인 및 비사용 시 엔드포인트 삭제 권장.
- **Amazon Bedrock**: API로 다양한 FM(AWS 큐레이션 + Cohere·Stability AI 등 서드파티) 사용/접근, 자체 FM 구축 불필요. 사용자 지정 가중치 가져오기+온디맨드 모드(약정 없이 사용량 과금). **Amazon Titan**: 아마존 범용 파운데이션 모델(텍스트 생성 등에 적합).
- **Bedrock 플레이그라운드**: 다양한 모델에 대해 추론 실험, 추론 파라미터 조정 → 사용 사례 최적 모델 탐색. **PartyRock**: Bedrock 기반 실습 플레이그라운드(재생목록, 게임, 레시피 등 앱 제작).
- 대부분 자체 LLM 훈련/호스팅 안 함(투자·연구·데이터·하드웨어 비용 문제).
- **벡터 데이터베이스**: 임베딩으로 저장, 고급 검색용 압축/인덱싱.
